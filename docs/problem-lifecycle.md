# Состояния карточки проблемы

Правила первой версии, 11 октября 2026. Уточнение
[спецификации](product-spec.md) для будущей устойчивой сущности `Problem`.
Карточка описывает конкретный дефект одного товара и сохраняет свой `problemId`
между запусками. Снимок кластера хранит доказательства конкретного запуска;
его ID не заменяет ID карточки. Изменение заголовка не создаёт новую проблему.

## Значение состояний

| Состояние | Значение |
| --- | --- |
| `new` | Найденная проблема ожидает проверки владельцем либо появилась снова после решения |
| `confirmed` | Владелец проверил доказательства и признал проблему актуальной |
| `rejected` | Владелец отклонил вывод; карточка и основания решения сохранены |
| `resolved` | Владелец отметил проблему решённой; история и доказательства сохранены |

Новая карточка создаётся в `new` только после сохранения пригодного снимка.
Одиночный сигнал показывается отдельно до достижения порога скрытой проблемы.
Состояние отражает решение пользователя, а признак скрытой проблемы —
доказательства выбранного запуска. `confirmed` не делает одиночный сигнал
скрытой проблемой, а `resolved` не удаляет жалобы из исторических метрик.

## Разрешённые переходы

| Из | В | Инициатор и условие |
| --- | --- | --- |
| `new` | `confirmed` | Владелец подтвердил проблему по цитатам |
| `new` | `rejected` | Владелец отклонил вывод, указав непустую причину |
| `new` | `resolved` | Владелец отметил решение без промежуточного подтверждения |
| `confirmed` | `resolved` | Владелец отметил решение |
| `rejected` | `new` | Владелец вернул карточку на проверку |
| `resolved` | `confirmed` | Владелец вручную переоткрыл проблему |
| `resolved` | `new` | Система обнаружила новое подтверждение после решения |

Остальные переходы запрещены. Коррекция ошибочного отклонения выполняется
через `rejected → new`, ошибочного решения — через `resolved → confirmed`.
Действие с уже установленным целевым состоянием не меняет время и историю.
Пользовательские переходы доступны только владельцу товара.

Для любого изменения сохраняются исходное и новое состояние, время сервера,
инициатор и причина при наличии. Для автоматического переоткрытия также
сохраняются `runId`, ID нового отзыва, упоминания и снимка.
Причина отклонения обязательна; комментарий к подтверждению и решению
необязателен. UI показывает последнее действие и доступную историю.
При `resolved` заполняется `resolvedAt`; после выхода из этого состояния
активное `resolvedAt` очищается, прежняя дата остаётся в истории.

## Повторное появление после решения

При решении карточки фиксируются время решения и известные подтверждения.
Автоматическое переоткрытие требует всех условий:

1. Текущий статус карточки всё ещё `resolved`.
2. Новый снимок уверенно сопоставлен с тем же дефектом того же товара.
3. Есть хотя бы один новый уникальный отзыв с валидной цитатой этого дефекта,
   впервые импортированный **после** времени последнего решения.
4. Результат отзыва и снимок уже сохранены; обязательный этап группировки
   этого запуска завершён успешно.

Для переоткрытия достаточно одного нового подтверждения любого рейтинга:
повторное появление и порог скрытой проблемы — разные условия.
Первичная дата импорта сохраняется при повторном импорте; дубликат старого
отзыва не становится новым доказательством. При совпадении времён с точностью
хранилища новое подтверждение не считается строго последующим.
Исходная дата отзыва показывается, но не подменяет время обнаружения:
старый по дате отзыв, впервые импортированный после решения, означает
«получено новое подтверждение», а не доказательство дефекта после исправления.

Повторный анализ прежних отзывов, новая формулировка модели, изменение
эмбеддингов или порога группировки сами по себе не переоткрывают карточку.
Отзыв, импортированный до решения, но проанализированный позже, также
не вызывает автоматического перехода. Его можно проверить вручную.

При выполнении условий происходит единственный переход `resolved → new`
с причиной `new_evidence_after_resolution`; UI показывает «Повторное появление»
и новую цитату. Повторная доставка того же результата не создаёт новое событие.
Новое доказательство у `new`/`confirmed` обновляет снимки без смены состояния.
У `rejected` оно отображается для проверки, сохраняя решение владельца;
автоматический переход из `rejected` не допускается.

## Пересчёт и конкурентные изменения

Сопоставление выполняется внутри товара по смыслу дефекта и доказательствам.
Совпадение категории или заголовка недостаточно. При неуверенном сопоставлении
снимок помечается как требующий проверки, без переноса пользовательского
состояния или автоматического переоткрытия. При разделении/объединении
кластеров история прежних карточек сохраняется; состояния не копируются
молчаливо в новые карточки.

Отсутствие проблемы в новом снимке не означает `resolved`: возможны другая
область запуска или отсутствие новых жалоб. Карточка сохраняет статус;
выдача выбранного запуска отдельно показывает наличие доказательств.
Ошибочный или незавершённый этап группировки не заменяет актуальный снимок.
Исторический просмотр не меняет состояние карточки.

Переход, запись истории и обновление версии карточки выполняются атомарно.
Пользовательское действие проверяет ожидаемую версию; при конкурентном
изменении возвращается конфликт с актуальным состоянием, UI обновляет данные.
Автоматическое переоткрытие также проверяет текущую версию и последнее решение.
После нового решения старое событие не применяется к нему повторно: условия
проверяются относительно нового `resolvedAt`. Поздний результат прежнего
запуска не перезаписывает пользовательское действие без повторной проверки.

## Сценарии будущей приёмки

| Условия | Ожидание |
| --- | --- |
| Новый пригодный кластер достиг порога | Карточка `new`, устойчивый ID, доступны цитаты |
| Подтверждение и решение владельцем | `new → confirmed → resolved`, два события истории |
| Отклонение без причины | Действие отклонено, состояние и история не меняются |
| Возврат отклонённой / ручное переоткрытие | `rejected → new` / `resolved → confirmed`, инициатор — владелец |
| Пересчёт тех же отзывов после решения | `resolved` сохранён, история не дублируется |
| Повторный импорт старого внешнего ID | `resolved` сохранён, время первого импорта не меняется |
| Новый отзыв после решения с тем же дефектом | `resolved → new`, одно событие и ссылка на новое доказательство |
| Новый отзыв без положительного контекста | Переоткрытие допустимо; признак скрытости считается отдельно |
| Старый отзыв впервые загружен после решения | Переоткрытие с пояснением о новом подтверждении, без вывода о дате дефекта |
| Импорт до решения, анализ после | Автоматического переоткрытия нет |
| Другой дефект того же аспекта / другой товар | Прежняя карточка не переоткрывается |
| Новые доказательства отклонённой проблемы | `rejected` сохранён; новое доказательство доступно для проверки |
| Проблема отсутствует в выбранной области запуска | Статус не меняется, отсутствие доказательств в этой области видно |
| Двойное событие / конфликт пользовательских действий | Один переход; конфликт не затирает более новое решение |
| Решение повторно после переоткрытия | Следующее событие проверяется относительно последнего решения |

Это контракт для последующей реализации и проверок. Сейчас `HiddenIssue`
имеет только флаг `resolved`, переключаемый без истории; пересчёт удаляет
старые карточки. Устойчивая сущность, состояния и сопоставление снимков
ещё не реализованы.
