# Единый провайдер анализа: local / OpenRouter

12 октября 2026. Пакет из десяти задач фазы 6. Новый интерфейс используется
анализом отзывов, сводкой и названием legacy-кластеров. Реальная локальная
модель и GPU не проверялись: они относятся к фазе 18. Автономная работа пока
не подтверждена. Новый формат жалоб с цитатами остаётся задачей фазы 8.

## Выбор режима

По умолчанию используется `LLM_PROVIDER=local`. Для старого `.env`, где новых
полей ещё нет, API запускается в local с URL `http://127.0.0.1:8080/v1` и
именем `local-model`. Это имя-заглушка конфигурации, не установленная модель.
При отсутствии сервера импорт и управление товарами работают, а анализ
отклоняется с понятной диагностикой. Существующие `.env` не перезаписываются.

Локальный сервер должен поддерживать совместимый HTTP-контракт:
`GET /v1/models` и `POST /v1/chat/completions` с текстовыми messages и
непотоковым ответом choices/message/content. В `LLM_MODEL` указывается
точный ID из списка моделей; совместимость конкретной сборки llama-server
подтверждается на втором ПК. Настройки runtime/context/GPU задаются отдельно.

Для явного облачного режима:

```dotenv
LLM_PROVIDER=openrouter
LLM_BASE_URL=https://openrouter.ai/api/v1
LLM_MODEL=YOUR_OPENROUTER_MODEL_ID
OPENROUTER_API_KEY=YOUR_API_KEY
```

При отсутствующих `LLM_BASE_URL` и `LLM_MODEL` облачный режим использует
старые OPENROUTER_BASE_URL/OPENROUTER_MODEL. Если новые поля присутствуют,
они имеют приоритет: при смене режима надо изменить их тоже. Настоящий ключ
обязателен только в облачном режиме. В local облачный ключ в HTTP не передаётся.
Сбой никогда не меняет провайдера или endpoint; редиректы отклоняются.

## Настройки

| Поле | Default и назначение |
| --- | --- |
| LLM_TIMEOUT_MS | 60000, таймаут одного HTTP-запроса, включая тело ответа |
| LLM_CONTEXT_TOKENS | 4096, заявленный бюджет контекста |
| LLM_MAX_OUTPUT_TOKENS | 1024, верхняя граница генерации, меньше контекста |
| LLM_CONCURRENCY | 1, общий лимит запросов всех сервисов одного процесса API |
| LLM_RETRIES | 2, максимум повторов сверх первой попытки, допустимо 0–3 |
| LLM_RETRY_DELAY_MS | 500, начальная задержка между повторами |
| LLM_MAX_RETRY_DELAY_MS | 5000, предел задержки |
| LLM_RESPONSE_FORMAT | json_object; также none / json_schema |
| LLM_CLOUD_DELAY_MS | 4000, пауза между отзывами облачного batch-анализа |

Local не имеет прежней четырёхсекундной паузы. Общая очередь HTTP-запросов
применяется также к сводке и названиям кластеров; отменённый ожидающий запрос
удаляется из очереди. HTTP-лимит действует внутри процесса. BullMQ ограничивает число одновременно
активных worker-запусков; сводка API имеет отдельный лимит. Согласование всех
GPU-запросов между процессами и измерения нагрузки остаются открытыми.

Для JSON-схемы надо явно выбрать json_schema и подтвердить поддержку runtime
или облачной моделью. Тогда запрос содержит JSON Schema со strict=true.
При json_object передаётся JSON-режим, при none формат не навязывается.
Во всех режимах результат JSON проверяется серверной Zod-схемой; невалидные
поля не превращаются в нейтральный успешный отзыв. Свободная текстовая сводка
использует проверенный envelope с непустым полным content.

Input не обрезается: прежнее slice(0,3000) удалено. При превышении допуска
`UTF-8 bytes > 4 × (contextTokens − maxTokens)` запрос отклоняется до HTTP.
Это грубый ограничитель размера, а не точный токенизатор. Автоматическое
разбиение длинных отзывов с позициями ещё не реализовано. Размер ответа
ограничен 2 МиБ, списка моделей — 8 МиБ; неверный UTF-8/JSON отклоняется.

## Проверка и ошибки

`GET /api/analysis/provider` возвращает только provider/model/contextTokens/
concurrency/responseFormat. `POST /api/analysis/provider/check` проверяет HTTP
список моделей и присутствие настроенного ID; оба маршрута требуют авторизации.
Проверка не запускает платную генерацию, не подтверждает качество, GPU-offload
или остаток квоты. Перед принятием анализа API делает ту же проверку;
недоступность возвращает 503 без задания и записанных результатов.

На страницах «Отзывы» и «Загрузка» показаны режим, модель, кнопка проверки
и её диагностический результат. URL сервера и API-ключ не выдаются браузеру.

Ошибки имеют коды cancelled/timeout/network/http/invalid_response/
model_unavailable/input_too_long. Ответы и логи ошибок адаптера не содержат
сырого вывода модели, текста отзывов или ключей. Отмена проходит через HTTP,
ожидание свободного слота и retry-паузу, не повторяется и не сохраняет поздний
результат в отзыв. Проверка модели тоже прекращается при закрытии HTTP-ответа.

Повторы разрешены для временного сбоя сети, таймаута, невалидного результата,
HTTP 408/429/500/502/503/504. Остальные HTTP-ошибки не повторяются.
Retry-After учитывается; если сервер требует паузу больше допустимой,
адаптер возвращает ошибку вместо преждевременного запроса. Первая попытка
плюс LLM_RETRIES — жёсткий предел одного вызова, общего цикла без лимита нет.

## Проверки и открытые пункты

`npm run check`: 119 API + 22 web тестов, TypeScript, ESLint и сборки.
HTTP-тесты на управляемом сервере выполняются для local и OpenRouter с
фиктивным ключом: несколько фиксированных JSON-результатов, форматы ответа,
недоступность, повторы, отмена, таймаут, параллельность и целостность входа.
Эти тесты проверяют программный контракт, не качество реальной модели.

`node scripts/verify-access-boundaries.mjs`: временная PostgreSQL и модельный
HTTP-сервер; авторизация конфигурации/проверки, отсутствие секретов, отказ до
старта при отсутствии модели, успешный анализ через local fixture и запись БД.
Облачная LLM и настоящий WB API не вызываются. Прежние проверки изоляции
двух аккаунтов, cookie, CSV и отчётов также выполняются.

Настройки и промпт теперь фиксируются в снимке устойчивого запуска; worker
использует сохранённые значения после рестарта. Разбиение длинных отзывов,
метрики/usage и версионированный кэш ещё не реализованы. Legacy-публикация
результатов остаётся переходной; группы с доказательствами ещё отсутствуют.
Подробности очереди: [analysis-worker.md](analysis-worker.md).

Контракты сверены с первичными источниками:
[OpenRouter chat completions](https://openrouter.ai/docs/api/api-reference/chat/create-a-chat-completion),
[llama-server](https://github.com/ggml-org/llama.cpp/blob/master/tools/server/README.md).
