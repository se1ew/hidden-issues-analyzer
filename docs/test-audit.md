# Настройка и проверка тестов

11 октября 2026. Команды `npm test`, `npm run test:api`, `npm run test:web`
запускают Vitest из локальных зависимостей. API использует Node environment,
web — jsdom и React-плагин без dev-прокси, чтобы тесты не поднимали Vite server.
Оба workspace сбрасывают реализации моков и восстанавливают spy перед тестом.

В API подключён `src/test.setup.ts`, исправлены пути моков относительно файла:
`./config/env.js`, `./lib/prisma.js`, `./lib/logger.js`. Общие моки БД не создают
PrismaClient, тестовое окружение не использует пользовательскую БД и ключ модели.
`reviews.test.ts` больше не дублирует моки setup и класс `HttpError`.
Web подключает jest-dom и очистку DOM после каждого теста.

| Файл | Раньше | Сейчас |
| --- | --- | --- |
| `stats.test.ts` | Копия фильтра и копия формулы hidden score | Публичные getOverviewStats/getSentimentTimeseries, область товара, пустые данные, параметры SQL и объединение рядов |
| `parsing.test.ts` | Копия регулярного выражения извлечения артикула | parseWildberries с моками fetch/БД, неправильные адреса, валидный импорт, отсутствие отзывов |
| `clustering.test.ts` | Локальные cosineSimilarity и centroid, которых нет в production-коде | recomputeHiddenIssues с реальным DBSCAN и моками эмбеддингов/LLM/БД, изоляция товаров и уникальные отзывы |
| `reviews.test.ts` | Production CSV-parser с повторными моками | Тот же parser с общим setup |
| `ProtectedRoute.test.tsx` | Не существовал | Реальный компонент и auth store: анонимный вход, сессия, выход |
| `env.schema.test.ts` | Не существовал | Реальная startup-схема, некорректные поля, production-заглушки и полнота шаблонов |

Набор проверяет текущее поведение. Тест legacy-метрик кластеризации не утверждает
соответствие новой спецификации скрытых проблем. Известные ограничения текущего
pipeline (одна связь проблемы у отзыва, удаление карточек при пересчёте,
отсутствие цитат и владельца товара) описаны в спецификации и не скрыты моками.
Современный контракт ещё требует отдельных тестов после реализации.

Моки исключают реальные сетевые обращения и не проверяют доступность Wildberries,
качество модели или реальную производительность БД. Интеграционная проверка
сервисов выполняется отдельно командой `npm run db:check`.
