# Редизайн ReviewLens

4 ноября 2026. Интерфейс существующего приложения переработан по предоставленному
визуальному референсу. API-контракты, Prisma-схема, авторизация, очередь и Socket.IO
сохранены. Синтетические данные находятся только в браузерном проверочном скрипте.

## Аудит и границы возможностей

Изучены README, рабочие страницы, область данных/синхронизация запусков, аналитика
и отчёты, маршруты, Query hooks, Zustand stores, API-клиент и существующие тесты.

| Раздел | Существующие возможности и изменения интерфейса |
| --- | --- |
| Обзор | Метрики выбранного товара/запуска, динамика тональности, распределение оценок, новые и скрытые группы, запуск анализа, AI-сводка |
| Проблемы | Серверные фильтры и сортировка, список/детали, поддержка и знаменатели, скрытость, последствия, цитаты с оценками, все доказательства с серверной пагинацией, решения, merge/split/link/restore с предпросмотром |
| Аналитика | Вкладки обзора, аспектов/жалоб, динамики и сравнения периодов; графики, таблица аспектов и ограничения сравнений |
| Отзывы | Поиск и фильтры в URL, таблица по 25 строк, аспекты, подробности, CSV всей выборки, подтверждение одиночного и массового удаления; настройки и история запусков в раскрываемом блоке |
| Товары | Карточки, поиск, фильтр источника, создание в диалоге, переименование, подтверждение удаления, переход к обзору |
| Импорт | CSV с этапами, сопоставлением, предпросмотром, валидацией и выгрузкой ошибок; ручной ввод; Wildberries и история заданий |
| Отчёты | Выбор формата/разделов/окна, формирование снимка запуска, история, статусы, повтор и скачивание |
| Настройки | Аккаунт, статистика, OpenRouter и локальная модель, каталог и ключ, проверка доступности, тема, диагностика, выход |
| Вход / регистрация | Общая форма, валидация, ошибки, показ пароля, существующая cookie-сессия |

Wildberries остаётся внутри импорта: `/parsing` перенаправляет на
`/upload?source=parsing`. Отдельного контракта страницы AI-анализа нет:
выполнение и история доступны в отзывах и общей панели синхронизации.

API групп не возвращает временной рост конкретной проблемы или измеренную
критичность. Эти значения не выдумываются. Показываются серверный приоритет,
сигналы, последствия и явно обозначенная неизвестная серьёзность. Правила
поддержки, положительного контекста и календарных сравнений не изменены.

AI-сводка формируется отдельным существующим запросом по товару; рядом указано,
что её область может отличаться от выбранного запуска. Смена товара закрывает
предыдущую сводку, запоздалый ответ не открывает её в другом товаре.

## Дизайн-система

`apps/web/src/styles/index.css` содержит семантические переменные обеих тем:
поверхность, фон, текст, вторичный текст, граница, акцент и мягкий акцент.
Светлая тема: фон `#F8F9FB`, белые карточки, текст `#111827`, акцент `#4F46E5`.
Inter поставляется локально с лицензией OFL, внешней загрузки шрифта нет.
Иконки Lucide, радиус карточек 12 px, тонкие границы и минимальные тени.

`components/ui.tsx`: PageHeader, MetricCard, MetricHint, StatusBadge,
SeverityBadge, ChartCard, FilterBar, DataTable, LoadingSkeleton, ConfirmDialog,
Rating, Tabs. QueryState отвечает за загрузку, ошибку и отсутствие данных.
Существующая Modal сохраняет удержание и восстановление фокуса, Esc и inert.
Layout выполняет роль AppShell; Header и Sidebar задают общую навигацию.

Графики вынесены в AnalyticsCharts. Распределение оценок использует пять
серверных `total` существующего `/api/reviews` с `pageSize=1`, рейтингом и
полной областью запуска. Проценты не считаются по одной странице отзывов.
Ключ кэша совместим с существующей инвалидацией по владельцу/товару/запуску.
Дополнительные серверные агрегаты и алгоритмы не вводились.

Таблицы прокручиваются внутри карточки. Длинные тексты переносятся, отзывы
в списке ограничены тремя строками и открываются полностью в диалоге.
Есть видимый фокус, клавиатурные действия, подписи полей, состояния ожидания,
отключение повторных отправок и подтверждение удаления. Тема сохраняется
существующим store. Страницы загружаются через React.lazy; графики не входят
в начальную загрузку формы входа.

## Проверки

- `npm run check`: TypeScript API/web, ESLint, 321 API-тест и 80 web-тестов,
  SQL-проверки миграций, production-сборки API и frontend.
- `node scripts/verify-analysis-runs.mjs`: временные PostgreSQL/Redis,
  отдельный worker, сохранение/восстановление запусков, HTTP-импорт, доказательства,
  подтверждение проблемы, снимок отчёта и скачивание; управляемая модель.
- `node scripts/verify-llm-settings.mjs` с Playwright: изоляция аккаунтов,
  шифрование ключей, сохранение провайдера/модели, отсутствие неявного облачного
  fallback; настоящий API и production SPA, регистрация/создание товара,
  refresh-cookie, настройки моделей и 48 сочетаний страниц/тем/ширин.
- `npm run test:ui:redesign`: управляемые ответы API в браузере, 64 сочетания
  восьми страниц, двух тем и ширин 1440/768/640/390; дополнительно авторизация,
  источники импорта, аспекты, длинные названия, масштаб 200%, цитата → точная
  публикация группы, серверный фильтр доказательств, фокус/Esc и повтор запроса.
  Переполнения страницы и ошибок JavaScript нет. Снимки и результаты:
  `.cache/redesign-check/`.

Для браузерных скриптов нужны Playwright и браузер. Можно указать
`PLAYWRIGHT_MODULE` и `BROWSER_EXECUTABLE`; для UI-скрипта также `WEB_BASE_URL`
(по умолчанию `http://127.0.0.1:5176`, сервер нужно запустить заранее).
Для проверки production на одном origin сборка выполняется с пустыми
`VITE_API_URL` и `VITE_WS_URL`, чтобы локальный `.env` не закреплял другой адрес.
Пользовательские env-файлы не изменены.

Реальные платные запросы OpenRouter, качество локальной GGUF-модели и доступность
Wildberries в интернете не проверялись. Интеграционные скрипты используют
временную БД и управляемые HTTP-источники; пользовательская БД не менялась.
Остаются прежние предупреждения об устаревшей базе Browserslist и неиспользуемом
параметре в API-тесте. После разделения страниц JS-chunk больше 500 kB отсутствует.
