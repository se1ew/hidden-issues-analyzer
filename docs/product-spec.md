# ReviewLens: спецификация первой версии

Версия 0.1, 11 октября 2026. Это целевое поведение для реализации и приёмки;
текущий код ещё не выполняет все требования. Решения ниже приняты как исходная
версия спецификации и могут уточняться по результатам проверки примеров.

## Пользователь и основной сценарий

Пользователь — продавец или аналитик, исследующий отзывы о своих товарах.
Он создаёт товар, импортирует отзывы, запускает анализ выбранного набора,
открывает повторяющуюся проблему, проверяет исходные цитаты и выгружает отчёт.
Результат помогает выбрать проблемы для проверки; вывод модели не доказывает
наличие дефекта у всей партии.

Товар принадлежит одному пользователю через обязательный `Product.userId`.
Отзывы, импорты, запуски, проблемы и отчёты наследуют доступ от товара.
Все операции и socket-подписки проверяют владельца. Командные проекты
не входят в первую версию. Старые данные без владельца не становятся общими.

## Что считается проблемой

Упоминание проблемы — утверждение автора о конкретном недостатке или
нежелательном последствии, подкреплённое дословной цитатой из исходного текста.
Похвала, отрицание дефекта, предположение без наблюдения и чужой опыт
не считаются подтверждением. Общая фраза «плохой товар» не даёт основания
выдумывать конкретный дефект. Несколько дефектов в одном отзыве сохраняются
отдельно; повтор одной жалобы в нём считается одним подтверждением.

Категории аспектов: `quality` (поломки, надёжность), `functionality`
(работа, шум, автономность), `material`, `size_fit`, `appearance`, `usability`,
`price`, `delivery`, `seller`, `packaging`, `other`. Для неоднозначных аспектов
допустим `other`, с исходной формулировкой. Отдельно хранится область жалобы:
`product`, `delivery`, `seller`, `packaging`. Проблемы доставки, продавца и
внешней транспортной упаковки показываются отдельно от проблем товара.
Дефект встроенной упаковки товара (например, протекающий флакон) — проблема
товара. Разные дефекты одного аспекта не объединяются только из-за категории.

## Критерий скрытой проблемы

Для каждого успешно проанализированного отзыва положительный контекст означает
`rating >= 4` **или** общую тональность `positive`. Противоречие рейтинга и
тональности показывается явно; рейтинг не заменяет анализ текста.

Скрытая проблема — один конкретный дефект товара, подтверждённый минимум
двумя уникальными отзывами в положительном контексте внутри выбранного товара
и области запуска. Два упоминания одного отзыва этого условия не выполняют.
Другие отзывы с тем же дефектом также входят в группу, но учитываются отдельно.
До достижения порога это одиночный сигнал, а не повторяющаяся скрытая проблема.

При отсутствии рейтинга положительный контекст допустим только при явно
полученной тональности `positive`. Такие подтверждения отображаются отдельно
как «без оценки; положительная тональность». При отсутствующем результате
анализа контекст неизвестен. Нулевое значение не подставляется вместо рейтинга.

Карточка содержит число всех уникальных отзывов с дефектом, число подтверждений
в положительном контексте, распределение рейтингов и тональностей, цитаты,
товар и запуск. Повторный импорт того же внешнего ID не увеличивает счётчик.
Одинаковый текст с разными достоверными внешними ID сам по себе не доказывает
дубликат; без ID возможный дубликат помечается, а решение о слиянии фиксируется.
Число независимых авторов показывается только при достоверных ID авторов;
число отзывов не называется числом покупателей.

## Метрики и ранжирование

`N` — число уникальных успешно проанализированных отзывов в снимке запуска,
`C` — число отзывов с конкретным дефектом, `H` — число таких отзывов в
положительном контексте. Показываются `C/N`, `H/C` и абсолютные `C`, `H`, `N`.
При нулевом знаменателе значение отсутствует, а не равно нулю процентов.
Ошибочные и необработанные отзывы не входят в знаменатель; их число видно рядом.

В первой версии карточки сортируются по `H` по убыванию, затем по `C`, затем
по устойчивому ID. Тяжесть выводится только из описанных последствий с цитатой;
если последствия не указаны, она неизвестна. Модуль тональности не измеряет
тяжесть. Текущий `hidden_score = severity × (1 − visibility)` считается legacy:
он не определяет принадлежность к скрытым проблемам и не выдаётся за
проверенную метрику. Новая формула ранжирования требует отдельной проверки.

## Данные и границы запуска

Каждый новый отзыв связан с товаром и импортом; хранится неизменный исходный
текст, источник, внешний ID при наличии, рейтинг, исходная дата и время импорта.
Пустой текст отклоняется. Отсутствующие дата, рейтинг и автор остаются `null`.
Исходная дата и время импорта не взаимозаменяемы. При фильтре по периоду отзывы
без даты исключаются с видимым счётчиком; без фильтра по периоду включаются.
Товар без отзывов показывает пустое состояние. Успешный анализ без жалоб —
корректный результат с пустым списком проблем.

Запуск задаётся товаром, всеми его отзывами или выбранными импортами, периодом
по исходной дате (начало включительно, конец исключительно, UTC) и режимом
«только новые» либо «повторный анализ». В режиме «только новые» берутся отзывы
без успешного анализа текущей версии конфигурации, включая прежние ошибки.
Состав и версии входных данных фиксируются до обработки. Новый импорт не
изменяет начатый запуск. Одновременно допускается один активный запуск товара.
Сохраняются версия модели, промпта, эмбеддингов, метода группировки и настройки.
Повторный анализ создаёт новый запуск, сохраняя историю старого.

## Жизненный цикл

Запуск: `queued → running → completed | partial | failed`.
`completed` означает успех всех выбранных отзывов и обязательных этапов;
`partial` — доступна пригодная часть результата, но есть ошибки отзывов или
этапов; `failed` — пригодного результата нет. Ошибка группировки не допускает
`completed`, даже если извлечение жалоб успешно. Пустая выборка завершается
как `completed` со всеми счётчиками 0 и пояснением «нет отзывов для анализа».
`queued` и `running` допускают переход в `cancelled` по запросу владельца.
После подтверждённой потери worker выполнявшийся запуск получает `interrupted`;
при уже принятой отмене — `cancelled`. Сохранённые задания в очереди
восстанавливают доставку после рестарта.
Сохранённые частичные результаты остаются доступны. Терминальный запуск
не возобновляется: повтор создаёт новый ID. UI показывает успехи, ошибки,
необработанные отзывы и текущий этап отдельно.

Точные условия, счётчики, отмена и защита от поздней записи определены
в [правилах жизненного цикла запуска](analysis-run-lifecycle.md).

Карточка проблемы: `new`, `confirmed`, `rejected`, `resolved`.
Владелец может подтвердить или отклонить `new`, решить `new`/`confirmed`,
вернуть `rejected` в `new` и переоткрыть `resolved` в `confirmed`.
Действия хранятся с временем и автором. Пересчёт создаёт снимок кластера и
не стирает карточку или её состояние. Если после решения новый отзыв с этим
дефектом попал в новый снимок, карточка возвращается в `new` с событием
«повторное появление». Старые отзывы при пересчёте её не переоткрывают.
Неуверенное сопоставление снимков требует проверки, а не молчаливого слияния.

Точные переходы, критерий нового доказательства и конкурентные действия
определены в [правилах состояний карточки](problem-lifecycle.md).

Удаление товара с активным запуском отклоняется до отмены и остановки worker.
Удаление товара после этого удаляет его зависимые данные и артефакты отчётов.
Отзыв из активного запуска удалить нельзя; удаление после завершения
инвалидирует затронутые результаты и отчёты, скрывает их из актуальной выдачи
и требует нового анализа. Исторические агрегаты не выдаются за актуальные.
Отдельное удаление исторического запуска допускается только для терминального
статуса и после удаления привязанных отчётов. Удаляются его результаты и снимки;
устойчивые карточки с другими снимками сохраняются. Карточка без оставшихся
доказательств исключается из актуального списка с объяснением причины.

## Назначение страниц

| Страница | Назначение |
| --- | --- |
| Дашборд | Выбранный товар, состояние данных, последний запуск, переход к проблемам |
| Загрузка | Выбор/создание товара, CSV или ручной ввод, итоги импорта и ошибки строк |
| Парсинг | Импорт из поддерживаемого источника в выбранный товар, прогресс и ошибки |
| Продукты | Товары владельца, создание, переименование и удаление |
| Отзывы | Исходные отзывы, фильтры, результаты и цитаты, запуск анализа |
| Аналитика | Метрики конкретного запуска, распределения, ограничения и AI-вывод |
| Скрытые проблемы | Карточки, доказательства, состояния и одиночные сигналы отдельно |
| Отчёты | PDF/DOCX выбранного запуска с областью, цитатами и ограничениями |
| Профиль | Данные пользователя и его сводная статистика |
| Вход/регистрация | Доступ к личным данным; выход очищает клиентский кэш |

AI-вывод и отчёт используют сохранённые результаты выбранного запуска,
не дописывают жалобы и доказательства. Исторический отчёт явно содержит дату,
область запуска и версии; внутренние пути файлов не публикуются.

## Проверка и известные расхождения

Начальный синтетический набор: [review-cases.json](fixtures/review-cases.json).
Правила оценки: [fixtures/README.md](fixtures/README.md).
Приёмка: [acceptance.md](acceptance.md). Набор не заменяет независимую разметку
реальных отзывов и не доказывает качество на других товарах.

Целевые запросы, ответы и ошибки определены в [плане API](api-contracts.md).

Сейчас анализатор возвращает строки жалоб без цитат и обрезает текст до 3000
символов. Запуск ограничен владельцем и выбранным товаром; при отсутствии
выбранного товара обрабатывает только товары текущего пользователя.
`Review.hiddenIssueId` пока позволяет связать отзыв только с одной проблемой;
пересчёт legacy-результатов удаляет прежние карточки в области владельца.
Новая схема с цитатами и снимками создана, но пайплайн ещё не переключён.
Владелец `Product.userId` обязателен для новых импортов, а у старых товаров
может отсутствовать до явного назначения; такие данные не показываются
через пользовательский API. Подробнее: [модель данных](data-migration.md)
и [принадлежность данных](ownership.md).
