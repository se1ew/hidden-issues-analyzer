# Извлечение жалоб и доказательств

18 октября 2026. Фаза 8 реализована программно; качество настоящей модели
ещё не измерено. Новый запуск сохраняет `review-evidence-v3` / `extraction-v3`.
Worker также читает ранее сохранённые v2 и legacy-v1 запуски.

## Что сохраняется

Общая тональность независима от рейтинга и тональности отдельных аспектов.
Позитивные и нейтральные аспекты сохраняются и при отсутствии жалоб.
`AspectMention.name` нормализуется по словарю `ru-aspects-v1`,
`originalName` сохраняет название из разобранного ответа модели. Неизвестный
аспект сохраняет имя и получает категорию `other`; смысловое сходство
не угадывается. Доставка, продавец и упаковка имеют отдельные категории.

Жалоба содержит ссылку на аспект, scope, описание, точную цитату и последствия
либо `null`. Только фактически описанная проблема (`assertion=experienced`)
становится IssueMention. Отрицание, предположение и отсутствие собственного
опыта не становятся дефектами. Классификацию утверждения выполняет модель:
программная проверка не доказывает правильность этой классификации.

Цитата должна встречаться в исходном снимке ровно один раз. Отсутствующая
или неоднозначная цитата и неподтверждённые цитатой последствия дают
`invalid_evidence`; результат отзыва считается ошибочным. Весь отзыв вместо
доказательства не подставляется. Неизвестные последствия остаются `null`,
уровень опасности не вычисляется. Схема отклоняет дополнительные поля,
включая придуманные confidence/probability/danger.

Точные дубли жалобы из одного диапазона удаляются по нормализованному
аспекту, scope, описанию и диапазону. Разные описания дефектов и разные
диапазоны сохраняются независимо. Смысловая группировка и подсчёт поддержки
по уникальным отзывам относятся к фазе 9.

`IssueMention.masking` сохраняет рейтинг (включая `null`), отдельные признаки
`highRating` и `positiveSentiment`, список оснований и версию
`positive-context-v1`. При отсутствии рейтинга `highRating=null`.
`positiveContext` означает сигнал жалобы в положительном контексте,
а не доказанную скрытую группу или вероятность. Оценка тональности
`sentiment_score` не является уверенностью или вероятностью.

## Координаты и чтение результатов

`GET /api/analysis/runs/:runId/inputs?page=1&pageSize=10` возвращает только
владельцу исходные снимки отзывов, статусы, аспекты и жалобы. Чужой или
отсутствующий запуск — 404; без токена — 401. `pageSize` ограничен 50,
порядок входов стабилен по ID; сырые ответы модели и приватная конфигурация
не выдаются. Ответ содержит `items`, `total`, `page`, `pageSize`, `runStatus`,
`offsetUnit="utf16"`, `offsetEnd="exclusive"`.

`quoteStart` — индекс с нуля, `quoteEnd` — исключительная правая граница
в кодовых единицах UTF-16 исходной строки:

```js
text.slice(quoteStart, quoteEnd) === quote
```

Перед вычислением и показом нельзя обрезать строку, менять переводы строк
или нормализовать Unicode. Emoji могут занимать две кодовые единицы.
Клиент проверяет единицу, границы и совпадение цитаты; неверный диапазон
не подсвечивается. Перекрывающиеся диапазоны объединяются только при
отображении, исходные жалобы остаются отдельными.

В истории запусков кнопка «Показать результаты» открывает исходный текст
с выделением цитат, все аспекты, последствия и основания положительного
контекста. Доступны страницы результатов и повтор запроса при сетевой ошибке.
При завершённом или отменённом запуске polling результатов прекращается,
даже если остались pending-входы.

## Обновление и проверки

Нужна миграция `20261018130000_evidence_metadata_and_retry_inputs`:

```powershell
npm ci
npm run db:generate
npm run db:deploy
```

Миграция добавляет nullable originalName/masking, не выдумывая сведения
для старых записей. Она также исправляет триггер повторов: разрешена точная
копия failed-входа родительского запуска после изменения или удаления
исходного отзыва. Подмена полей, копирование успешного входа и чужого товара
отклоняются; неизменяемость сохранённых снимков остаётся обязательной.

`npm run check` включает 175 API + 30 web тестов, SQL-проверку всех миграций,
TypeScript, ESLint и обе production-сборки. `npm run test:sql` исполняет
сохранённый SQL и PL/pgSQL в отдельной PGlite БД в памяти; пользовательские
данные не затрагиваются. Эта проверка не проверяет Prisma, Redis или
отдельные процессы worker и не заменяет приёмку очереди.

25 размеченных примеров проходят production HTTP-адаптер с управляемыми
ответами, затем схему и подготовку доказательств. Дополнительно проверены
сарказм с заданной разметкой, длинный текст без обрезки, пустой ответ,
несколько аспектов, отрицание, доставка, дубли, неизвестный рейтинг,
сохранение исходного имени, emoji/CRLF и ошибочные диапазоны.
Это проверка обработки заданной разметки, а не измерение качества LLM.

Проверка настоящей очереди остаётся открытой: Docker Desktop недоступен
из-за ошибки сокета Secrets Engine. После восстановления нужны
`node scripts/verify-analysis-runs.mjs` и
`node scripts/verify-access-boundaries.mjs`.
