# CSV: предпросмотр, проверка и импорт

20 октября 2026. HTTP-импорт переведён на потоковое чтение и транзакционные
пакеты по 100 записей с сохраняемыми контрольными точками. Детали повторной
отправки и ограничений — [аудит задач](backlog-audit.md).
Страница «Загрузка» требует выбрать существующий товар по ID либо явно создать
новый. Название не используется для поиска существующего товара. Новый товар
и импорт сохраняются одной транзакцией; при ошибке записи новый товар не остаётся.
На странице «Товары» можно отдельно создать пустой товар, переименовать и удалить
его. Удаление с активным импортом, анализом или отчётом блокируется; завершённая
история и её файлы удаляются вместе с товаром.

## Формат и ограничения

- UTF-8, необязательный BOM. Невалидный UTF-8 и UTF-16 отклоняются; автоматической
  замены повреждённых символов и угадывания Windows-1251 нет.
- Разделители: запятая, точка с запятой, табуляция. Автоматическое определение
  учитывает кавычки заголовка; разделитель можно выбрать явно.
- Первая запись — заголовки: до 100 непустых колонок, до 200 символов в названии.
  Имена уникальны после удаления краевых пробелов, приведения к нижнему регистру
  и замены пробелов на `_`.
- Файл до 25 МиБ; до 10 000 записей без заголовка; до 65 536 символов в записи.
  Превышение размера файла/числа записей даёт 413, повреждённая структура — 422.
- Пустые физические строки пропускаются. Номер в диагностике — номер CSV-записи
  с учётом заголовка, начиная с 2; перенос внутри кавычек не создаёт новую запись.
- Текст: непустой после проверки пробелов, до 10 000 символов; оригинальные
  пробелы и переносы сохраняются. Даже короткое «ОК» считается отдельным отзывом.
- Рейтинг: целое 1–5 или пустое поле. Неверное значение отклоняет запись целиком.
- Дата: `YYYY-MM-DD` или ISO timestamp с секундами и явным `Z`/смещением.
  Проверяются календарная дата и диапазоны времени. Пустое поле допустимо;
  неоднозначные даты и timestamp без часового пояса отклоняются.
- ID отзыва/автора: до 200 символов, краевые пробелы удаляются; пустое поле
  означает отсутствие ID. Прочие колонки не импортируются.

Автоматические имена колонок: text/review/comment/feedback/review_text/content/
текст/отзыв; rating/score/stars/mark/рейтинг/оценка; date/created_at/review_date/
published_at/дата; external_id/review_id/id_отзыва; author_id/id_автора.
Через сопоставление можно использовать любые другие заголовки. Одну колонку
нельзя назначить двум полям; необязательные поля можно явно отключить.

## Текущий API

Все операции требуют access token. Сохранённые импорты и их ошибки доступны
только владельцу товара и партии; чужой/неизвестный ID дают одинаковый 404.

| Операция | Путь и параметры |
| --- | --- |
| Предпросмотр | `POST /api/reviews/upload/csv/preview`, multipart `file`, `delimiter?`, `mapping?` |
| Импорт | `POST /api/reviews/upload/csv`, те же поля + ровно один из `productId`/`productName` |
| Сохранённый итог | `GET /api/reviews/imports/:batchId` |
| Ошибки записей | `GET /api/reviews/imports/:batchId/errors`, CSV UTF-8/BOM |
| Ручной отзыв | `POST /api/reviews/upload/text`, `text`, `rating?`, ровно один из `productId`/`productName` |
| Создать товар | `POST /api/products`, `{name}` |
| Просмотреть товар | `GET /api/products/:id` |

`mapping` — JSON-строка с полями text/rating/date/externalId/authorExternalId;
значения — имена заголовков. Пустая строка отключает поле, отсутствие поля
в исходном запросе включает автоматическое определение. Ответ предпросмотра
возвращает итоговое сопоставление, включая явно пустые значения, разделитель,
первые пять записей, счётчики и первые 100 диагностических сообщений.
Он не создаёт товары/партии/отзывы. Перед записью сервер заново проверяет файл.

Импорт сохраняет корректные записи и полную диагностику отклонённых.
`totalCount = validCount + errorCount`; `validCount = count + skippedCount`.
В БД `UploadBatch.count` — всего, `addedCount` — добавлено. errorCount считает
записи, а список ошибок — поля, поэтому у записи может быть несколько сообщений.
При ошибках строк статус partial, иначе completed. При отсутствии корректных
записей — 422 с диагностикой, без записи партии или создания нового товара.
Ошибка транзакции не даёт частично записанную партию. Диагностика не содержит
сырых значений ошибочных строк; экспорт не раскрывает чужие данные.

Повтор внешнего ID внутри товара и источника csv пропускается, первое
происхождение не перезаписывается; новые появления имеют ссылки на партии
с исходными номерами CSV-записей. Одинаковые тексты без ID сохраняются отдельно.
В другом товаре тот же файл создаёт независимые отзывы.

## Проверки и оставшаяся работа

`npm run check` и `node scripts/verify-access-boundaries.mjs`: проверка формата,
ошибок, исходного текста, номеров записей, неизменности БД при предпросмотре,
частичного результата, повторного импорта, другого товара, авторизации и
скачивания диагностики. Тесты интерфейса проверяют явное подтверждение,
обязательный товар и повторную проверку при смене сопоставления колонок.

В память не загружается весь HTTP-файл: он временно сохраняется на диск и
читается потоком. Первый проход проверяет файл без записи в БД, второй сохраняет
контрольные точки. При сбое статус interrupted; повторная отправка того же файла
пропускает готовые пакеты. По умолчанию ключ операции включает владельца, SHA-256
файла, товар/новое название, разделитель и сопоставление. Повтор завершённой
операции возвращает прежний batchId и его первоначальные итоги.

Без ID одинаковые строки внутри файла сохраняются отдельно. Между разными
файлами неоднозначные совпадения не удаляются; повтор того же файла распознаётся
по операции и номеру записи. API-клиент может явно задать `Idempotency-Key` для
отдельной операции. Повтор ключа с другими параметрами даёт 409. Файлы после
HTTP-запроса удаляются; возобновление требует повторно отправить исходный файл.
