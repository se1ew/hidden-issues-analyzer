## Импорт и удаление

HTTP-загрузка сохраняется во временный файл в `apps/api/uploads`, а не в Buffer
всего файла. Поток проверяет UTF-8, структуру и ограничения. Первый проход не
меняет БД; второй сохраняет по 100 CSV-записей. Число ошибочных записей и полная
диагностика фиксируются заранее, статус `completed` появляется только после
последнего пакета. Ошибки строк дают `partial`, сбой сохранения — `interrupted`.

Идемпотентность по умолчанию определяется владельцем, SHA-256 файла, товаром
или явно новым названием, разделителем и итоговым сопоставлением колонок.
Повтор того же запроса возвращает прежний batchId и его первоначальные итоги.
При потере ответа или рестарте нужно повторно отправить тот же файл с теми же
параметрами: готовые пакеты пропускаются, включая строки без внешнего ID.
Файл после завершения HTTP-запроса удаляется; для возобновления нужна повторная
отправка. Это не автоматическое продолжение без исходного файла.

Без внешнего ID одинаковые строки внутри файла остаются разными отзывами.
Составной ключ — контекст файла и номер записи; текст сам по себе не используется
для удаления дублей. Между разными файлами совпадение текста, даты и автора
считается неоднозначным: записи сохраняются. С внешним ID действует прежний
ключ товар/источник/ID, первое происхождение не перезаписывается. Заголовок
`Idempotency-Key` позволяет API-клиенту создать отдельную операцию; повтор ключа
с другим содержимым отклоняется с 409. Другой товар имеет независимый импорт.

Удаление товара блокируется при активном импорте, анализе или отчёте. После их
завершения владелец удаляет товар, историю, доказательства и метаданные одной
транзакцией; файлы удаляются только внутри каталога отчётов. Защита опубликованных
снимков сохраняется для обычных изменений: исключение удаления ограничено ID
товара и текущей транзакцией. Чужой ID возвращает 404.

## Модель и кэш

Новые запуски имеют `methodVersion=extraction-v4`; ранее сохранённые v2/v3
продолжают исполняться с прежним контрактом. Текст делится по UTF-8-бюджету
с сохранением UTF-16-позиций и целых Unicode-символов, не более 16 фрагментов.
Жалобы из перекрытия с одинаковым дефектом и пересекающимися позициями устраняются.
Разные жалобы и непересекающиеся упоминания сохраняются.

Общая оценка тональности длинного текста — взвешенное по неперекрывающейся длине
среднее оценок фрагментов; пороги ±0.2. Способ записывается в диагностику и виден
рядом с результатом. Это отдельное программное правило, не оценённое качество
понимания всего отзыва настоящей моделью.

`LLM_MODEL_VERSION` должен содержать неизменяемую ревизию/дайджест модели.
Значение `unverified` по умолчанию отключает кэш извлечения. Ключ учитывает
владельца, исходный текст, модель и версию, prompt/метод/JSON-схему, настройки
провайдера и версию разбиения. Сохраняется только проверенный структурированный
результат на семь дней; при чтении цитаты проверяются заново. Ошибки кэша не
прерывают анализ. Пароли и API-ключи в ключ/запись кэша не входят.

Доступный token usage суммируется по ответам провайдера, включая ответы,
отклонённые перед повтором. Если провайдер не отдаёт usage, значение неизвестно;
оценка стоимости не выдумывается. Публичные результаты содержат длительность,
число фрагментов, usage и признак кэша.

## Проверки

- `npm run check`: типы, lint, 292 API + 62 web теста, SQL миграций, обе сборки.
- `npm run test:integration:migration`: старая схема → backup/restore → все миграции;
  явное назначение владельца, ограничения и неизменяемые снимки.
- `npm run test:integration:access`: сессии, два аккаунта, анонимный доступ,
  вложенные ID, события, импорты и скачивание.
- `npm run test:integration:runs`: PostgreSQL/Redis/отдельный worker, потеря очереди,
  рестарт, отмена, частичные результаты, отчёты, восстановление файлов и БД;
  CSV с ошибкой в третьем пакете и конкурентным повтором; загрузка WB на
  управляемых ответах; удаление товара с запечатанной историей.
- Сквозной сценарий в том же runner: регистрация → товар → CSV → реальный worker
  с управляемой HTTP-моделью и заранее заданными кэшированными векторами → цитаты
  → подтверждение → сохранённый DOCX → скачивание.
- `npm run test:production:web`: собранные assets и прямое открытие вложенных
  маршрутов через preview. Конечный production-хостинг относится к фазе 18.

CI в `.github/workflows/ci.yml` запускает установку, проверки, сборки, временную
инфраструктуру и миграции на Node 24. Его удалённый запуск на GitHub в этом
аудите не выполнялся; соответствующие команды проверены локально.

Edge/Playwright: новая загрузка источника проверена на ширинах 1440/768/390
в светлой и тёмной темах; переполнения и ошибок JavaScript нет. Проверены
артикул, ожидание фонового задания, отмена и понятное предложение CSV после
ошибки формата. Ответы API в этой браузерной проверке управляемые.

PDF просмотрены после Poppler, DOCX — после `render_docx.py` и LibreOffice
в изолированном контейнере `hia-document-qa:local` без сети. Проверены все страницы
обычного отчёта, длинного текста/таблицы и пустых разделов. Исправлены ширины
колонок DOCX и разрыв блока ограничений. Числа обычного отчёта сверены со снимком.
Проверка 2000 синтетических доказательств измеряет объём/ресурсы, а не качество
модели; измерения сохраняются в `.cache/operations-check/render-benchmark.json`.
