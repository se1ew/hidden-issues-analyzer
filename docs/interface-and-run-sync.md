## Поведение

Все кнопки запуска используют useRunAnalysis. После ответа API общий store
сохраняет runId, состояние и область нового запуска. Запоздалый ответ товара A
не меняет выбранный пользователем товар B. Отмена не закрывает прогресс до
подтверждённого сервером терминального состояния.

AnalysisRunSync находится в авторизованном Layout. Он восстанавливает активный
запуск из списка API независимо от страницы и sessionStorage, читает детали,
принимает уведомления Socket.IO и использует polling. При переподключении
socket подписывается снова. Смена владельца/товара очищает старое состояние;
ошибка сети сохраняет последнее известное состояние. После завершения
обновляются только данные затронутого товара, а не все запросы каждые пять секунд.

Общая панель показывает товар, запуск, период исходных отзывов, покрытие,
ошибки, оставшиеся отзывы и время анализа. Выбор запуска применяется к обзору,
отзывам, проблемам и аналитике. В режиме загруженных отзывов можно применить
период и создать анализ этого периода. Период сохранённого запуска фиксирован.
Смена запуска очищает выбор исторической публикации и предпросмотр правки.

Импорт обновляет живые списки, статистику товара и общие счётчики владельца,
сохраняя кэш неизменяемых снимков запусков. Решение по проблеме обновляет
группы только этого товара; правка группировки также обновляет их историю и
счётчики. Отзывы исторического запуска доступны для чтения: удаление источника
из такого представления отключено. Старый оптимистический delete больше не
уменьшает total на страницах, где удаляемого отзыва не было.

## Интерфейс

Визуальная основа — локальный экспорт Stitch precision_analytical_b2b.
Перенесены спокойный фон, плоские поверхности, синий акцент, ясные границы и
типографика. Основные цвета/поверхности задаются CSS-переменными обеих тем.
Упрощены карточки, кнопки, поля и badges; статусы имеют текст.

Layout содержит одну панель области и ссылку пропуска навигации. Мобильное
меню отсутствует в DOM, пока закрыто, и открывается как диалог. Общая Modal
имеет имя, role=dialog, aria-modal, начальный фокус, удержание Tab/Shift+Tab,
закрытие Esc, восстановление фокуса и inert для фонового интерфейса.
Она используется деталями отзыва, предложением анализа, AI-сводкой и меню.
Таблица отзывов прокручивается внутри карточки; длинные названия переносятся.

QueryState различает загрузку, ошибку и пустую выборку. Ошибка сервера не
становится пустым списком товаров или сообщением «проблем не найдено».
Основные страницы позволяют повторить запрос. Кнопки блокируются на время
действия, поля имеют labels, интерактивные элементы — видимый focus-visible.

Login/Register используют одну форму: access token остаётся в памяти,
refresh-cookie обрабатывается API-клиентом. Ошибка видна в форме, пароль
проверяется по лимиту UTF-8 (72 байта), вход допускает прежний короткий пароль.
Профиль показывает ошибку запроса и позволяет отозвать текущую сессию через
серверный logout. Ошибка выхода сохраняет сессию и позволяет повторить действие.

ProductsPage показывает источник, число загруженных отзывов, последний запуск,
его статус, покрытие и ошибки. API получает последний запуск отдельно по
каждому принадлежащему пользователю товару. Отсутствующий запуск не подменяется
нулевым покрытием; ограничение удаления товара с историей выводится из API.

## Проверки

`npm run check`: 235 API + 48 web тестов, TypeScript, ESLint, обе SQL-проверки
миграций в PGlite и production-сборки. Новые проверки покрывают разделение
invalidation, сохранение снимков, медленный ответ запуска после смены товара,
общее восстановление запуска, фокус/Esc/возврат фокуса и формы авторизации.

`npm run test:integration:runs` требует Docker в PATH. Скрипт сам создаёт
PostgreSQL 16 и Redis 7 со случайными именами/портами на localhost, применяет
миграции и удаляет собственные контейнеры. Он не читает пользовательскую БД.
Управляемый HTTP-провайдер проверяет контракт; это не проверка качества модели.

Пройдены двойное создание запуска, владение, неизменяемые исходные данные,
повтор только ошибок, частичный успех/все ошибки/отмена/пустой результат,
lease и heartbeat, повторная доставка, восстановление строки без Redis job,
падение и перезапуск отдельного worker, потеря Redis-очереди и общий permit
API/worker. Redis CLIENT KILL разрывает реальные TCP-соединения; работающий
worker переподключается и завершает сохранённый запуск.

Увеличен deadline интеграционного скрипта с 7.5 до 90 секунд: BullMQ должен
успеть дождаться штатного истечения 30-секундной блокировки и проверки stalled
job. Это изменение теста; производственные таймауты не менялись.

На настоящем Express + Prisma + временном PostgreSQL сверены JSON-ответы
деталей, обзора, отзывов, аспектов, пустых групп и последнего запуска товара.
Проверены partial/cancelled/completed с пустой областью/interrupted, чужой
владелец и 409 scope_mismatch.

Edge через Playwright: шесть страниц × две темы × ширины 1440/768/640/390 =
48 сочетаний. Проверены длинное название товара, внутренний скролл таблицы,
масштаб 200% через CSS zoom (отдельно от ширины viewport),
отсутствие горизонтального переполнения страницы, открытие мобильного меню,
удержание фокуса, Esc и возврат фокуса, детали отзыва, ошибка API и повтор.
Ответы API в визуальной проверке управляемые; демонстрационные данные не
попали в приложение. Скриншоты и результаты текущего прогона:
`.cache/ui-check/`. Ошибок JavaScript нет.
