```powershell
node scripts/prepare-embeddings.mjs --cache .cache/portable-models
node scripts/prepare-embeddings.mjs --cache .cache/portable-models --offline
```

Первый вызов закрепляет commit, загружает файлы, считает векторы и сохраняет
manifest SHA-256. Второй проверяет файлы и запрещает fetch. Он успешно выполнен
на CPU Windows (~2.1 s) и в Linux production-образе с `--network none` (~7.4 s).
Это проверка загрузки и вычисления эмбеддингов; качество группировки LLM и
производительность GTX 1080 по этим числам не оцениваются.

В production постоянный кэш — `/app/models_cache` в именованном volume `models`.
В `deploy/.env.example` закреплена указанная ревизия. Перенесите каталог целиком,
включая `embedding-assets.json` и подкаталоги модели/ревизии. После копирования
в volume повторите `node /app/scripts/prepare-embeddings.mjs --cache
/app/models_cache --offline` внутри worker-контейнера. Не переносите `node_modules`
Windows в Linux. Векторный ONNX и tokenizer не требуют Windows-зависимостей.

## Доступ ко второму ПК

Для Windows 10/11 установить OpenSSH Server в PowerShell администратора:

```powershell
Add-WindowsCapability -Online -Name OpenSSH.Server~~~~0.0.1.0
Start-Service sshd
Set-Service -Name sshd -StartupType Automatic
Get-Service sshd
Get-NetFirewallRule -Name OpenSSH-Server-In-TCP
```

Имя пользователя: `$env:USERNAME`, локальный IPv4: `ipconfig` (Wi-Fi/Ethernet).
Подключение из той же сети: `ssh USER@IP`. Если штатное правило firewall
отсутствует, создать его по инструкции Microsoft; при доступе только из LAN
ограничить RemoteAddress значением LocalSubnet. Проброс порта роутера для
первой локальной проверки не нужен. Пароль вводится в SSH-клиенте на своём ПК;
для автоматической работы далее потребуется настроенный ключ.

Источник: [OpenSSH Server for Windows](https://learn.microsoft.com/en-us/windows-server/administration/openssh/openssh_install_firstuse).

GPU-отчёт не требует Node, npm или проекта целиком. Достаточно скопировать
`scripts/check-gpu.ps1` на второй ПК и выполнить:

```powershell
powershell -NoProfile -File .\check-gpu.ps1 -ExpectedGpu 'GTX 1080' -OutputPath .\gpu-check.json
```

В репозитории команда: `powershell -NoProfile -File scripts/check-gpu.ps1`.
Отчёт по умолчанию сохраняется в `.cache/gpu-check.json`, исключённый из Git.

в отчёте появятся версия и список устройств. Наличие устройства ещё не
подтверждает фактическое вычисление на GPU; нужен лог загрузки и offload.

## Кандидат для пробного запуска

Предварительный вариант: llama.cpp с CUDA 12.x и официальный
`Qwen/Qwen3-4B-GGUF`, квантование Q4_K_M. Это кандидат для испытания,
а не установленная или уже выбранная рабочая конфигурация.
Версию runtime, совместимость драйвера и точное имя GGUF нужно закрепить
после проверки второго ПК; скачивать случайную latest-сборку заранее не следует.

GTX 1080 относится к Pascal: CUDA 13 удаляет поддержку offline-компиляции
и библиотек для этой архитектуры. Поэтому для CUDA-варианта требуется
совместимая сборка на CUDA 12.x; поддержку GPU и offload проверять фактически.
Источник: [NVIDIA CUDA 13 release notes](https://docs.nvidia.com/cuda/archive/13.0.0/cuda-toolkit-release-notes/).

Начальные параметры эксперимента: context 4096, parallel 1, bind 127.0.0.1,
порт 8081 (порт 8080 занят приложением). Количество GPU-слоёв выбирается по свободной памяти и логу, а
не по паспортному объёму. При нехватке памяти сначала уменьшить контекст
или offload; результат и ограничения сохранить. Режим thinking для Qwen3
отключить штатным способом конкретной версии runtime и проверить полный ответ.
Эти настройки не являются измеренными оптимальными значениями.

Источники: [сборка llama.cpp](https://github.com/ggml-org/llama.cpp/blob/master/docs/build.md),
[llama-server](https://github.com/ggml-org/llama.cpp/blob/master/tools/server/README.md),
[официальный Qwen3-4B GGUF](https://huggingface.co/Qwen/Qwen3-4B-GGUF).

## Что сохранять при измерениях

Точный runtime version/commit, backend и список устройств; драйвер;
репозиторий модели, имя файла, revision и SHA256; квантование;
context, parallel, GPU layers; версию промпта; полные ответы и ошибки.
Для каждого опыта — время загрузки модели отдельно от первой генерации,
время прогретого запроса и последовательной пачки, GPU-память до/во время/после.
Память измерять периодическими наблюдениями, а не только двумя снимками.

Начальный набор — [25 размеченных отзывов](fixtures/README.md).
Проверять валидность JSON, отсутствие выдуманных жалоб, точность цитат
и отрицания. Семантические жалобы сверять по смыслу; идентичность строки
модельного описания эталонному `defect` не требуется. Ошибки и пустые успешные
результаты различать. После скачивания всех артефактов отдельно проверить
работу без интернета; локальный HTTP-адрес сам по себе этого не доказывает.
